FireArc — Boot Chain & Build Guide

Development trust domain (QEMU Q35) · enforced chain complete through TPM2-bound data · generated 2026-10-21

1 · The enforced boot chain

Every arrow is a verification. Nothing executes unless the previous stage verified it. Any failure stops the boot — the machine powers off, it never falls back to something unverified.

0
Host ROM anchor — QEMU loads flash only if its SHA-256 matches the pinned digest

coreboot RO + vboot key block are immutable from the VM's point of view

1
coreboot — vboot protected RW — the mutable RW section must be signed by the vboot keyset

signature verified before the Dasharo payload executes · tampered RW ⇒ refused

2
Dasharo / EDK II — Secure Boot — SecureBoot=1 · SetupMode=0, PK/KEK/db enrolled

every EFI binary checked against db · unsigned / wrong-key ⇒ refused before launch

3
systemd-boot — signed with the sb key, at the firmware entry on the ESP

menu locked, zero timeout · loads exactly one UKI

4
UKI — systemd-stub — kernel + initrd + cmdline + policy, one signed PE

measures every section into PCR 11 · publishes /.extra/tpm2-pcr-signature.json /.extra/tpm2-pcr-public-key.pem

5
initrd — root integrity gate — full dm-verity pre-verify, then read-only mapping

expected hash/salt live inside the signed UKI · root tamper ⇒ poweroff · extends PCR 11 with the phase

6
Real root (read-only) — systemd boots from the verity mapping

runtime reads stay under verity · tamper later ⇒ EIO · prints FIREARC_DEV_BOOT_OK

7
Data unlock probe — only after the root gate: TPM2 token unseal, attach, detach

refusal never blocks the verified root · verdict on serial: UNLOCK_OK / REFUSED / TOKEN_ABSENT

8
LUKS2 data volume — per-device, aes-xts-plain64, 512-bit

keyslot 0 = recovery credential (escrow pending) · keyslot 1 = TPM2 token

PCR board — what seals the data volume

PCR 7 — plain binding (Secure Boot state)
extended byEDK II: PK/KEK/db contents + SecureBoot flag
changes whenSecure Boot keys are re-enrolled
used bytoken PolicyPCR — must match exactly to unseal
current valuestable across boots · asserted every boot
PCR 11 — signed policy (measured boot)
extended bysystemd-stub (UKI sections) + pcrphase-initrd
current sha2568b034d5545cf6e54… (changes with every rebuild — by design)
used byPolicyAuthorize: valid iff .pcrsig signed by pkfp 4aaa9ed7…
why signeda new UKI + new signature re-authorizes without re-enrollment

Click any stage above for its full detail. Rule of thumb: PCR 7 = which keys, PCR 11 = which software.

2 · TPM2 enrollment — one session, three proofs

Interrupted session = adopted, never wedged

  • enroll_pending marker set before power-on
  • Load tolerates region drift only while the marker is set
  • Next run validates the on-disk token host-side and adopts it — or refuses
  • No silent re-seal of an already-sealed volume

Moved disk = refused (proven)

  • dev9's disk on dev10's fresh swtpm: verified root still boots
  • Token unseal fails — the blob only opens on the sealing TPM
  • FIREARC_DATA_UNLOCK_REFUSED on serial, boot contract fails loud
  • Copying the whole old TPM state across would defeat this — production must bind identity to the physical TPM

3 · Build & run — the just recipes

Build is a staged pipeline: each stage hashes its inputs, produces evidence under build/, and the next stage consumes only verified outputs. Stages auto-resolve their dependencies — no labels to pass.

Shorthand: just build runs the whole pipeline; just verify-build re-checks every stage's evidence without rebuilding.

Typical sessions

# first time on this machine
just bootstrap && just build && just keys && just vboot-keys && just pcr-keys \
  && just firmware-sign && just enroll && just verify-build

# qualify the chain (the gates)
just check-firmware-vboot && just check-secure-boot && just check-boot

# make a device and bring up its data volume
just device-provision --name devA        # disk + flash + swtpm + LUKS2 + recovery credential
just data-enroll --name devA             # TPM2 token (PCR 7 + signed PCR 11), in-boot validation
just device-boot --name devA --count 3   # three cold starts, all markers + identity asserted

# watch it with your own eyes
./scripts/boot-live devA

# clean disk after experiments
just prune --keep 0

4 · Moving to real hardware — what changes, what ODMs must deliver

The QEMU chain relies on a host that checks the flash digest. Real hardware has no host. Everything below replaces that anchor and the emulator conveniences.

REPLACE Root of trust

  • Required: Intel Boot Guard with FireArc-owned fused key (OEM/BTG profile), or coreboot RO in SPI with hardware write-protection (PR0/PRR set at provisioning)
  • Without one of these, "verified RW" has no anchor — do not ship
  • Verify protection empirically on the board: write-protect bits read back, external SPI flash attempts fail

REPLACE Secure Boot keys

  • Enroll FireArc-owned PK/KEK/db/dbx (today: dev enrollment on Dasharo defaults)
  • PK private key stays offline; db rotation via KEK-signed update; dbx policy from day one
  • PCR 7 changes on re-enrollment ⇒ staged measurement-policy transition before any key rotation (Phase 10 item 6)

REPLACE swtpm → discrete TPM 2.0

  • Required: dTPM 2.0 (rev ≥1.38), SHA-256 bank, TIS or CRB interface, NV + PCR state surviving power loss
  • Identity is permanent — no state-copy rescue; TPM clear/replacement must break unlock (it does by design)
  • Anti-rollback needs a monotonic counter — allocate TPM NV index early
  • Avoid fTPM unless its attestation properties are accepted in the threat model

REPLACE Firmware updates

  • UEFI capsule (signed) or signed coreboot updater — whatever the pinned coreboot/EDK II actually supports
  • Must preserve SMMSTORE/NVRAM across updates; A/B firmware or a firmware rollback index
  • Never overwrite a complete flash image in place — stage, verify, switch (same rule as the OS)

CHECK Board minimums

  • CPU: x86-64 with AES-NI (LUKS2 xts), NX, SMAP; Intel NICs (i225/i226/i350/X550 class) — no Realtek for the data plane
  • RAM ≥ 8 GB · storage ≥ 32 GB (matches the GPT layout: ESP 1G, root A/B 4G + 128M hash each, data = remainder)
  • UART header for manufacturing/recovery console; SPI flash external programming header or dual-BIOS switch
  • TCO watchdog for hang recovery; RTC battery for monotonic time
  • coreboot board support must emit the TPM2 event log (log area reserved) so the PCR replay tool works unchanged

CHECK Flash & boot flow

  • SPI descriptor locks + SMM variable-store protection verified in tests (BIOSWE/BLE bits)
  • Disable EFI shell, network boot, option ROMs, external boot in the release profile — keep USB boot manufacturing-only via policy toggle
  • Board AGESA/microcode updates change PCRs 0–3 — version them in the measurement policy

PROCESS Manufacturing

  • Provisioning station: per-device LUKS2 + TPM enrollment at factory, two-person control for the recovery credential escrow (item 7 decision pending)
  • Audit trail per device: serial ↔ disk UUID ↔ TPM EK/AK ↔ escrow record
  • Rehearse escrow recovery + credential rotation on isolated clones before field units exist (items 14–15)

PROCESS Qualification deltas

  • Power-loss campaign: real brown-outs/relay cuts during update + boot (500-cycle, PDF G-target)
  • Every QEMU test (tamper, transplant, tamper-EIO, gates) re-run on hardware — swtpm state copies must not migrate as production identities
  • Fresh hardware TPM identities; re-run the full move/refusal matrix on real boards

Still missing before any of that (current gaps)

  • FireArc-owned PK/KEK/db + dbx policy · A/B slots + boot counting + fallback (Phase 4) · bounded recovery interface (Phase 9)
  • Firmware update + trust rotation (Phase 10) · RAUC OS updates (Phase 6) · health checks/auto-rollback (Phase 7)
  • Escrow custody path (Phase 5 item 7 — owner decision pending)
